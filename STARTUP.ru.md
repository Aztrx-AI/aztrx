## 1. Одним предложением

**Aztrx AI — это автономный стресс-тестер для веб-приложений** — он гоняет твоё
приложение как враждебный пользователь, находит падения (даже те, которые
проглатывает React Error Boundary), сопоставляет их с точной строкой в исходнике и
*доказывает* каждый баг исполняемым Playwright-тестом-воспроизведением вместо строки
из лога. При желании он ещё и чинит их.

Весь питч — три глагола: **найти → доказать → починить.**

## 4. Архитектура — как это работает внутри

Aztrx — **развязанный событийно-ориентированный конвейер**. Модули общаются только
через типизированный `EventBus` (`src/core/eventBus.ts`); `orchestrator.ts` связывает их
вместе (гексагональ — оркестратор можно заменить на облачный приёмник).

```
[ CDP-перехватчик ] ─▶ [ кольцевой буфер действий ] ─▶ [ классификатор (fingerprint) ]
                                │
[ проверенный .patch ] ◀─ [ LLM-починка ] ◀─ [ ddmin-минимизатор ] ◀─ [ резолвер sourcemap ]
                                │
                   [ Playwright spec (.spec.ts) ] ─▶ [ валидатор flake-rate ]
```

Стадии (в коде названы F1–F14):

| Стадия | Модуль | Что делает |
| --- | --- | --- |
| F1 | `interceptor.ts` | Ловит `console.error`, `pageerror`, `crash` рендерера, `requestfailed` и 5xx-ответы. `console.error` — ключевой трюк: Error Boundary логируют туда вместо перевыброса, поэтому `window.onerror` никогда не срабатывает для проглоченных ошибок. |
| F2 | `recorder.ts` | Кольцевой буфер последних 25 действий + каскад селекторов `data-testid → text → CSS path`. |
| F3 | `classifier.ts` | Fingerprint + дедупликация находок, присваивает severity (`crash`/`error`/`warning`/`noise`), подавляет `.aztrx/baseline.json`. |
| F4 | `resolver.ts` | Сопоставляет минифицированные фреймы стека с файлами/строками через sourcemaps. |
| F5 | `fuzzer.ts` + `domWalker.ts` | Зерновой хаос-фаззер (click/hover/keypress/select/мусорный ввод) + детерминированный обход. |
| F5-http | `httpFuzzer.ts` | Собирает реальные эндпоинты приложения, шлёт враждебные запросы (переполнение query, type-confusion в JSON, инъекция заголовков), превращает каждый 5xx в воспроизведение. |
| F6 | `networkGuard.ts` | Сетевая политика deny-by-default (только целевой origin + `--allow-host`). |
| F7 | `minimizer.ts` | `ddmin` — дельта-отладка, сжимает трассу действий до минимума, который ещё воспроизводит. |
| F8 | `specCompiler.ts` | Генерирует автономный, чистый Playwright `.spec.ts`. |
| F9 | `validator.ts` | Прогоняет несколько раз → вердикт `deterministic` / `flaky` / `unreliable`. |
| F10 | `heal/` | Замкнутая починка: redact → LLM → AST-gate → git worktree → `tsc` → тест → проверка. |
| F11 | `telemetry/` | Опциональные анонимизированные кортежи crash→repro→patch (локально или `--share-data`). |
| F12 | `cloud/` | Опциональная выгрузка очищенных находок в панель. |
| F13 | `summarize.ts` + `heal/apply.ts` | Человекочитаемое «рентген»-резюме + опциональное применение проверенных патчей. |
| F14 | `diagnose.ts` | Однострочный заголовок «почему + что поменять», выводимый рядом с каждой находкой crash/error — детерминированный, опирается на форму сообщения V8, ключ не нужен. |

**Swarm** (`swarm.ts`): один запуск = список воркеров, каждый со своим контекстом
браузера, рекордером и классификатором. По умолчанию один воркер-«обход»;
`--swarm`/`--workers` разворачивают обход + несколько зерновых фаззов + HTTP-фаззер,
находки сливаются по fingerprint. Авто-размер ограничен **8 воркерами** (каждый — это
полный контекст Chromium, ~200–400 МБ ОЗУ).

**LLM-слой** (`src/core/llm.ts`): один `complete()` с двумя транспортами — нативный
Anthropic (по умолчанию) и любой OpenAI-совместимый эндпоинт `/v1/chat/completions`,
выбираемый через `AZTRX_API_BASE`.

## 5. Функции (и как каждая была сделана)

### Обнаружение
- **`run <url>`** — детерминированный обход: посещает каждый видимый `a/button/input/select/textarea/[role=button]/[onclick]`, кликает/заполняет по порядку документа, и теперь **восстанавливается после навигации** (пересканирование + `goto(startUrl)`) вместо того, чтобы остановиться на первой ссылке.
- **`--fuzz`** — зерновой хаос (воспроизводим через `--seed`). Богатый словарь: двойные клики, hover, keypress, смена select-опций, скроллы, мусорный ввод.
- **`--http-fuzz`** — серверная поверхность атаки (на стороне Node, не браузера).
- **`--swarm` / `--workers <n>`** — параллельное обнаружение.

### Доказательство
- **`--repro`** — ddmin → компилятор spec → валидатор flake-rate. Каждая находка crash/error получает исполняемый `.spec.ts` и вердикт (`[deterministic 3/3]`).

### Починка (LLM)
- **`--heal`** — генерирует патч, проверяет его (redact + AST-безопасность + без новых import/eval/child_process), компилирует, прогоняет твой тест-сьют, воспроизводит в изолированном git worktree. Проверено *до* того, как ты это увидишь.
- **`--fix`** — версия одной командой: find → explain → heal → apply, с запросом `y/N`. Никогда не коммитит.
- **`--explain`** — человекочитаемое резюме (LLM при наличии ключа, детерминированный офлайн-фолбэк иначе; `--lang ru` для русского).
- **`modernize <file>`** — переписывает устаревший JS/TS файл в современный синтаксис, применяется только после подтверждения (с проверкой парсинга).

### Аутентификация
- **`--login`** — сам находит форму логина (`input[type=password]`), заполняет креды, сохраняет сессию, продолжает авторизованным.
- **`--storage-state <path>`** — использует сохранённый Playwright storage-state.

### Ship / CI
- **`--fail-on`** — exit 1 при любом crash/error (для CI-гейтов).
- **`--pr-comment`** — пишет GitHub PR markdown-комментарий с воспроизведением.
- **`--badge`** — пишет автономный SVG-бейдж статуса.
- **`--upload` / `--api-key` / `--cloud-url`** — стримит находки в облачную панель.
- **`--telemetry` / `--share-data`** — опциональные анонимизированные данные (локально или выгружаются).

### Инструменты
- **`studio`** — локальная панель (`:7331`) со стримингом находок вживую.
- **`init`** — генерирует `aztrx.config.ts` и добавляет `.aztrx/` в gitignore.

### Мульти-провайдер LLM
Любая модель через один OpenAI-совместимый эндпоинт:
```bash
export AZTRX_API_BASE="https://openrouter.ai/api/v1"  # или api.x.ai/v1, api.openai.com/v1, ...
export AZTRX_API_KEY="your-key"
export AZTRX_MODEL="anthropic/claude-sonnet-5"
```
Покрывает Grok, DeepSeek, Gemini, GPT, Kimi, Mistral, OpenRouter и локальные Ollama/vLLM.

## 6. Философия проектирования (идеи за решениями)

1. **Доказывай, а не сообщай.** Ров — исполняемое воспроизведение: строку из лога можно отмахнуться, а `[deterministic 3/3]` Playwright-тест — нет.
2. **Чёрный ящик, а не белый.** CDP + перехват консоли работают на любом фреймворке; никаких хуков React/Next. (Изначальная идея интроспекции Fiber была отброшена.)
3. **Безопасно по умолчанию.** Сеть deny-by-default, deny-list разрушительных действий (никогда не кликает delete/pay/logout), redact перед любым LLM-вызовом, изолированный git worktree, никогда не коммитит, `.aztrx/` в gitignore, закреплённая supply chain.
4. **«Отчёт как учитель».** Вместо вываливания всех флагов инструмент подсказывает *следующий* флаг после запуска (`Tip: run with --fix …`), чтобы пользователь учился по необходимости, а не зубрил.
5. **Прогрессивное раскрытие.** `--help` сгруппирован по смыслу (Detect / Prove / Fix / Report & ship / Auth), алиасы и нишевые ключи скрыты (но работают), а `--fix` — один запоминающийся глагол.
6. **Без привязки к вендору.** Любой LLM-провайдер через `AZTRX_API_BASE` — «работает с тем ключом, который у тебя уже есть» — это базовое требование.
7. **Бесплатно и с открытым кодом.** Всё — detect, prove, heal, облако — под Apache-2.0 и бесплатно. Единственная трата — твой собственный ключ модели.

## 9. Что сделано недавно (v0.1.1 → v0.5.2)

**0.5.2 — песочница перестала съедать ваш `node_modules`.** Песочница починки
линкует `node_modules` репозитория в свой временный worktree, а на Windows эта
ссылка — junction. `git worktree remove --force` идёт *сквозь* junction, поэтому
штатная уборка рекурсивно удаляла настоящий `node_modules` — на каждом запуске
`--fix` под Windows. Нашлось это запуском цикла по-настоящему, а не чтением кода:
собственный `node_modules` этого репозитория вернулся пустым. Теперь уборка
снимает ссылки на каталоги до того, как worktree попадёт в git. Фикс проверен
дважды — регрессионный тест падает без него, и A/B на живом проекте: без фикса
реальный прогон починки опустошает `node_modules` цели, с фиксом sentinel-файл
остаётся нетронутым.

**0.5.2 заодно заставил воспроизведение действительно воспроизводить.** Прогон
цикла на живом Next.js-приложении — и разбор того, *почему* из трёх его крашей
лечился только один, — вскрыл четыре дефекта в середине конвейера. Главный:
записанная трасса не говорила, на какой странице она снята, поэтому находка на
`/agents` давала трассу из кликов, которые что-то значат только там; при
воспроизведении они не находили элементов, краш не достигался, и баг, срабатывающий
на каждый клик, получал `unreliable 0/3`. С исправлением этого и трёх дефектов
тайминга и патча ниже **3 из 3 находок на том приложении теперь доказаны как
`[deterministic 3/3]` и вылечены вообще без API-ключа** — на том самом
приложении, где раньше лечилась 1 из 3.

**0.5.2 заодно закрыл разрыв между тем, что репозиторий говорит, и тем, что он делает.**
Все CI-сниппеты в README пинили `@v0.5.2` — тег, которого нет на origin, для версии,
которой нет в npm. Каждый, кто скопировал сниппет, получал падающий джоб с сообщением
`aztrx did not run (exit code: N)` — сформулированным так, чтобы его нельзя было принять
за вердикт о приложении, а значит читающимся как инфраструктура, а не как неправильный
README. Пины подняли коммитом с заголовком «Release 0.5.2 … on npm» за четыре коммита до
публикации, о которой этот заголовок говорит. Ошибкой был не сам подъём, а его
преждевременность. Пины вернулись к последней версии, которую посторонний
действительно может поставить, и три проверки теперь держат их там: README,
`action.yml` и переиспользуемый workflow обязаны совпадать друг с другом, и ни один
не может называть версию *впереди* `package.json`. Именно это сделало выпуск 0.5.2
механическим — опубликовать, поставить тег, поднять пять пинов, один push.

**0.5.1 — починка теперь доказывается, а не предполагается.** Раньше пропатченный
патч мог отчитаться как исправленный, *ни разу не выполнившись*: клиентские находки
отдавались статикой, поэтому `.tsx` приезжал в браузер текстом, который он не
исполняет; реплеи сохраняли исходные абсолютные URL и возвращались в непатченный
код; а недоступная страница не слала телеметрию — что неотличимо от исправленного
бага. Всё закрыто: приложение поднимается, если есть start-команда; каждый
записанный URL переписывается на отданный origin; `ReplayResult.loaded` теперь
гейтит `fixed`. Оба PR-открывателя стейджут только те файлы, что починили, вместо
`git add -A` — автоматическая починка больше не может закоммитить ваш рабочий стол.

- **Неверная строка на Next.js, и чего это стоило** — фрейм `webpack-internal://` несёт позицию в модуле, который сгенерировал webpack, а не в `.tsx` на диске: Next в dev-режиме сообщал `app/page.tsx:29:21` для краша на строке 15. Путь — настоящий путь к исходнику, поэтому файл находился и показывалась уверенно неверная строка: сниппет, в котором бага нет. Это же тихо убивало бесплатный фикс: `generateRulePatch` ищет свойство на указанной строке, находил `</div>` и отказывался — поэтому каждая находка уходила в платную модель. Сигнал есть в самом сообщении — `(reading 'agents')` может бросить только строка, читающая `.agents`, — значит строка, которая её не читает, доказуемо неверна, а настоящая находится. Неоднозначность (несколько незащищённых чтений, различить нечем) остаётся как есть, а не угадывается. Проверено на живом проекте: строки встали на 15/13/12, а `--heal` выдаёт фикс **вообще без API-ключа**.
- **Трасса теперь несёт свои переходы** — записанная трасса не говорила, на какой странице она снята: обходщик попадает на каждый маршрут через `page.goto`, а это не порождало ни одного действия, поэтому находка на `/agents` давала трассу из кликов, которые что-то значат только там. При воспроизведении с стартового URL каждый из них не находил элемента, краш не достигался — и баг, срабатывающий на каждый клик, получал вердикт `unreliable 0/3`, что читается как «ваш баг плавающий», а на деле означает «мы не воспроизвели ваш баг». `navigate` уже понимал каждый потребитель трассы — не хватало только производителя. Он берётся из `framenavigated`, по одному разу на URL: Playwright шлёт это событие **дважды** на один `goto` (измерено на Chromium, не предположено), а буфер действий всего на 25. Заодно обходчик перестал перезагружать стартовую страницу, на которой уже стоит: браузер нормализует `http://host` в `http://host/`, поэтому сравнение строк говорило «другая страница» и каждый прогон платил за лишнюю полную загрузку с повторным запуском всех mount-эффектов.
- **Воспроизведённый переход теперь ждёт перед действием** — обходчик ждёт 300 мс после своего `goto`, прежде чем что-то трогать, значит каждый записанный селектор разрешался на странице, которой дали 300 мс на отрисовку; replay, кликающий в момент коммита навигации, требует того, чего при записи не было. Измерено: 0 мс — **0/3**, 300 мс — **3/3**. Та же трасса, то же приложение.
- **Replay больше не перестаёт смотреть слишком рано** — он ждал фиксированные 300 мс после последнего действия, а это ровно собственная асинхронная задержка реального приложения, поэтому одна и та же трасса воспроизводилась через раз. Теперь это опрос, возвращающийся в момент появления отпечатка: окно — потолок, а не задержка, и платит за него только трасса, идущая к вердикту `unreliable`, — то есть именно тот случай, где ошибиться нельзя.
- **Бесплатный rule-фиксер больше не калечит spread-синтаксис** — `/\.(?=[a-zA-Z_$])/` совпадает с третьей точкой в `...s`, поэтому `{ ...s, [id]: result.ok }` превращалось в `{ ..?.s, [id]: result?.ok }`, а уже защищённое `d?.agents` — в `d??.agents`. И то и другое синтаксические ошибки, и AST-гейт их отклонял — правильно, но пользователь видел `rejected` без единого слова о том, что мусор выдал *rule-движок*, а бесплатный фиксер молча отказывался от каждой строки со spread или с уже существующим `?.`, то есть от большей части React-кода. Лечится lookbehind. Его предел задокументирован: это регулярка по строке, а не лексер, поэтому `.name` внутри строкового литерала на строке краха тоже будет переписан.
- **Рекламируемая версия проверяется, а не запоминается** — `uses: owner/repo@vX` с несуществующим тегом сообщает не о плохом пине, а `aztrx did not run`, что сформулировано как инфраструктура. Пять мест, называющих устанавливаемую версию (два в `README.md`, два в `action.yml`, одно в `uses:` самого reusable-workflow), обязаны совпадать, и ни одно не имеет права *опережать* `package.json`: отставать — нормальное состояние между релизами, опережать — значит называть версию, которой нет нигде. Равенство достигается только так: поднять пины, закоммитить и запушить тег тем же пушем. `tests/action.test.ts` раньше утверждал обратное — что пин *равен* версии из `package.json`, — и именно это правило и вынудило преждевременный подъём; намерение было верным, но оно приравнивало «этот релиз» к «этому дереву», а они совпадают лишь после пуша тега.
- **README проверяется по коду** — его справочные таблицы обещают 52 флага и 10 переменных окружения, а ни один из списков не был связан ни с парсером, ни с `process.env`. Удалённый флаг хотя бы отвечает `error: unknown option`; переименованная переменная окружения не отвечает ничем — она читается как undefined, фича молча откатывается к дефолту, и искать нечего. Теперь оба списка проверяются как подмножество кода, с защитой, которая громко падает, если паттерны перестанут совпадать, вместо пустого прохождения. Оба списка на момент добавления были чистыми; ценность в том, что они обязаны остаться такими.
- **Тарбол, который ставит пользователь, проверен, а не предположен** — `npm pack` в чистый проект, `npm i` тарбола, и затем: `--version` отдаёт 0.5.2, сгруппированный `run --help` рендерится, все пять записей `exports` резолвятся (`aztrx-cli`, `/vite`, `/next`, `/mcp`, `/package.json`), а guard `--repo` (см. ниже) присутствует в отгруженном артефакте — выходит с кодом 1 и ничего не создаёт. Затем главное: страница с засеянным null-deref на 127.0.0.1, отсканированная *собранным из тарбола* билдом — найдено, сопоставлено с `index.html:9:32`, диагностировано, сжато до 1 шага, скомпилировано в самостоятельный спек и провалидировано **`✓ deterministic 3/3`**. Получившийся спек — чистый семистрочный Playwright-тест. 479 кБ, 142 файла.
- **`--repo` проверяется, а не принимается на веру** — commander забирает значение `<required>`-опции даже если оно выглядит как флаг, поэтому `aztrx run <url> --repo --fix` ставил корнем проекта буквальную строку `--fix`. `path.resolve` превращал её в `<cwd>/--fix`, и прогон после этого *успешно* завершался против каталога, который инструмент сам придумал, оставляя внутри `.aztrx/events.jsonl` и `report.html` — код возврата 0, ни одного предупреждения. Нашлось как осиротевший `C:\Users\dchap\--fix\`, в котором лежал только `.aztrx/`; воспроизведено на опубликованной 0.5.1, чтобы убедиться, что форма ровно такая. Теперь корень обязан существовать и быть каталогом, а отказ для пути, чей последний сегмент — флаг, говорит об этом прямо. Пустой каталог, который никто не может объяснить, — отказ хуже сообщения об ошибке, потому что о нём ничто не сообщает.
- **Отказ провайдера теперь называет себя** — пустой ответ приходил к пользователю как `Unexpected end of JSON input`, что указывает на наш парсер, а не на модель. Оба транспорта теперь бросают ошибку со stop-причиной («лимит токенов достигнут до того, как был выдан текст…», «провайдер упал в середине ответа»), а `data.error` проверяется, потому что OpenRouter сообщает об отказах вышестоящего провайдера в теле под HTTP 200.
- **Потолок токенов в починке — 8192** — патч это несколько сотен токенов, но reasoning-модель тратит бюджет сначала на размышление и на 2048 упиралась в потолок, не выдав ни символа. Это потолок, а не списание: платите за фактически выданные токены, так что запас бесплатен для моделей, которые не рассуждают.
- **Цикл доказан, а не просто подключён** — у find → prove → heal → apply теперь есть настоящий прогон за спиной: живой ключ OpenRouter, реальный краш, `✓ deterministic (3/3 runs)`, `✓ healed`, `✓ applied heal-llm.html (1 edit)`. Чтобы до этого дойти, понадобилась новая фикстура — все остальные в репозитории это null-deref, на них отвечает бесплатный rule-движок, и до LLM-пути дело не доходило.
- **Редизайн CLI** — сгруппированный `--help`, глагол `--fix` (вместо `--magic-fix`), скрытые алиасы (`--swarm`, `--auth`, `--login-*`).
- **Реструктуризация README** — ведёт с истории «одна команда, ноль настройки».
- **Фикс версии** — баннер читает из `package.json` (было захардкожено).
- **Фикс TUI** — события `action`/`route` воркеров теперь пробрасываются в живую панель (счётчики стояли на 0).
- **Фикс walker** — пересканирование + восстановление после навигации (17 действий на странице ссылок вместо 1).
- **Фиксы шума** — `net::ERR_ABORTED`/`ERR_BLOCKED_*` отфильтрованы; заблокированные guard-ом сторонние запросы теперь `blockedbyclient`.
- **Мульти-провайдер LLM** — любая OpenAI-совместимая модель.
- **`suggestNext`** — подсказка «следующий флаг» после запуска.
- **`--version` / `-V`** — читает `VERSION` из установленного `package.json`, поэтому не может разойтись с тем, что отдал npm. До 0.5.1 его не было.

## 10. Что осталось / открытые вопросы

- **Облачная панель** — `api.aztrx.app` (`server/`) существует, но не полностью подключена/запущена.
- **Переключение домена** — `aztrx.app` сейчас отдаёт маркетинговую страницу; QA-панель должна была жить там.
- **Запуск** — Show HN / публичный запуск.
- **Флагманское демо** — цифры за заявкой о recall из README записаны: `bench/frameworks/RESULTS.md` (13/13 найдено, 12/12 детерминированных воспроизведений) и `bench/RESULTS.md` (13/13, 11/12).
- **Осиротевший тег `v0.5.0`** — тег есть на origin, но 0.5.0 никогда не публиковался в npm, поэтому `uses: Aztrx-AI/aztrx@v0.5.0` падает с ETARGET. Ничто не велит пользователям пинить его (документированный пин — `v0.5.2`), и падение безопасное: проверка сообщает «aztrx не запускался», а не вердикт о приложении. Но тег — мёртвый груз. Удалить его или опубликовать 0.5.0 — оба варианта требуют осознанного решения, поэтому он оставлен как есть.
- **Порядок релиза — почему пин отстаёт от дерева, а не опережает его** — это нормальное состояние между релизами: `main` и `package.json` идут впереди, а документированный пин стоит на *последней версии, которую посторонний действительно может поставить*, потому что пин что-то значит только когда существуют и тег, и тарболл. 0.5.2 — выпущенное состояние, поэтому сегодня все пять совпадают; следующий релиз снова откроет этот разрыв, и намеренно. Порядок не переставляется:
  1. `npm publish` — никогда с `--ignore-scripts`; именно `prepublishOnly` пересобирает `dist/`, а закоммиченный `dist/` устарел.
  2. `git push && git tag v0.5.2 && git push origin v0.5.2` — тег ставится **после** публикации. Тег до публикации — ровно так `v0.5.0` и стал сиротой выше.
  3. Поднять рекламируемую версию — `README.md` (три ссылки), `action.yml` и `.github/workflows/aztrx-pr.yml` (две ссылки) — закоммитить и запушить этот коммит **тем же пушем, что и тег**. `tests/version-pins.test.ts` и `tests/action.test.ts` следят, чтобы все пять совпадали и ни одна не опережала `package.json`; именно они делают шаг 3 механическим, а не «не забыть».

  Тег, запушенный раньше своей публикации, — сломанный пин для каждого, кто скопирует README из репозитория; поднятый раньше публикации пин в README — та же поломка на шаг раньше. И то и другое — почему пин отстаёт от дерева между релизами, и почему совпадение всех пяти сегодня — факт о 0.5.2, а не постоянное свойство `main`.
